## Version-gated client behavior

> Source: https://code.visualstudio.com/docs/copilot/reference/copilot-settings

- `chat.agent.enabled` requires **VS Code 1.99+**. On older VS Code the setting does not exist and agents are unavailable — check the editor version before debugging the setting.

> Source: https://docs.github.com/en/copilot/reference/copilot-feature-matrix

- GitHub's feature matrix is organized by IDE platform **and IDE version history**. When a feature is missing in Visual Studio, JetBrains, Eclipse, Xcode, or NeoVim, check that matrix for the version that introduced it before assuming a plan or policy problem. GitHub recommends the latest stable IDE and Copilot extension versions.

## Model catalog snapshot

> Source: https://docs.github.com/en/copilot/reference/ai-models/supported-models

The catalog listed in `ide-and-models.md` is a **2026-08-05 snapshot**. Model availability changes frequently and varies by plan tier, IDE, and admin policy. Never assert that a specific model is or is not available today from this snapshot alone — direct the user to the model picker in their client, which reflects their plan and org policy.

Capability boundaries confirmed on that date:

- 1M-token context window: **VS Code and Copilot CLI only**.
- Configurable reasoning levels: VS Code, Copilot CLI, and the cloud agent.

## Stable constraints (unchanged and unlikely to move quietly)

> Derived: each item is sourced in `cloud-agent.md`, `customization-files.md`, or `admin-and-governance.md`.

These are worth quoting confidently because they are architectural rather than rollout-dependent:

- Cloud agent session cap: **59 minutes**, non-extendable.
- One repository, one branch, one pull request per cloud agent task.
- The `copilot-setup-steps` job name requirement.
- Firewall incompatibility with self-hosted runners and with Windows runners.
- Audit log retention: **180 days**, and no client-session/local-prompt capture.
- Instruction precedence: personal → repository → organization.
- Custom agent precedence: repository → organization → enterprise.
