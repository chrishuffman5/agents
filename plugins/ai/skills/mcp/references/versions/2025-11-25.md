# MCP spec revision 2025-11-25 (stable baseline)

Read this to confirm what is normative in the revision production code should target as of 2026-08-05.

## Status

> Source: https://modelcontextprotocol.io/specification/2025-11-25
> Source: https://modelcontextprotocol.io/docs/learn/architecture

**2025-11-25 is the current stable MCP specification revision.** This is what production clients and servers should target. Treat it as the default for every answer unless the user explicitly says they are on the `2026-07-28` draft.

## What this revision defines

> Source: https://modelcontextprotocol.io/specification/2025-11-25

- **Message format:** JSON-RPC 2.0.
- **Stateful connections** with explicit server/client **capability negotiation** — each side only offers or uses features the other declared support for.
- **RFC 2119 keywords** (MUST/SHOULD/MAY, per BCP 14 / RFC 2119 / RFC 8174) are used normatively throughout.

**Server primitives:** Tools (functions the model can execute), Resources (context/data for the user or model), Prompts (templated messages/workflows for users).

**Client primitives, all non-deprecated in this revision:** Sampling (server-initiated agentic/recursive LLM interactions), Roots (server-initiated inquiries into URI/filesystem boundaries), Elicitation (server-initiated requests for additional user information).

**Additional utilities:** configuration, progress tracking, cancellation, error reporting, logging. Logging is a first-class utility here — it is *not* deprecated in this revision.

## Lifecycle and headers specific to this revision

> Source: https://modelcontextprotocol.io/specification/2025-11-25/basic/transports

- The classic **initialize-once** lifecycle applies: `InitializeRequest` → `InitializeResult` → `InitializedNotification`. There is no `server/discover` method and no per-request `_meta` discovery fields.
- Over Streamable HTTP, clients **MUST** send `MCP-Protocol-Version: 2025-11-25` on every request after initialization.
- A server that receives no `MCP-Protocol-Version` header, and has no other way to determine the version, **SHOULD** assume `2025-03-26`.
- Resource change watching uses `resources/subscribe`-style subscription rather than the draft's generalized `subscriptions/listen`.

## Authorization in this revision

> Source: https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization

The OAuth 2.1 profile documented in `../authorization.md` is the 2025-11-25 profile. Notable requirements that arrived or hardened here:

- MCP servers **MUST** implement RFC 9728 Protected Resource Metadata; clients **MUST** use it for authorization-server discovery.
- Authorization servers and clients **SHOULD** support Client ID Metadata Documents; Dynamic Client Registration is retained only as a **MAY**, for backwards compatibility with earlier MCP auth spec versions.
- RFC 8707 Resource Indicators are **MUST** for clients, sent on both authorization and token requests regardless of AS advertisement.

## Security best practices in this revision

> Source: https://modelcontextprotocol.io/specification/2025-11-25/basic/security_best_practices

The eight attack classes in `../security.md` (confused deputy, token passthrough, SSRF, session hijacking, local server compromise, OAuth URL validation, stdio proxy scenarios, scope minimization) are all part of the 2025-11-25 security best practices document.
