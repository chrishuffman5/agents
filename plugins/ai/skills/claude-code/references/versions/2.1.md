# Version-gated behavior — Claude Code v2.1.x

Read first when a documented feature "doesn't work" for a user. Everything below is tied to a specific CLI release; confirm `claude --version` before debugging further. Behavior is stated as of the 2026-08-05 documentation fetch.

## Gates by release

> Source: https://code.claude.com/docs/en/google-vertex-ai.md

- **v2.1.121+** — X.509-based Workload Identity Federation supported for Google Cloud's Agent Platform credentials.

> Source: https://code.claude.com/docs/en/permission-modes.md

- **v2.1.126+** — `bypassPermissions` mode also exempts protected-path writes. Before this, protected paths were still gated.
- **v2.1.142+** — `permissions.defaultMode: "auto"` is ignored in `.claude/settings.json` and `.claude/settings.local.json`; it must be set in user scope so a repository cannot grant itself auto mode.
- **v2.1.200** — `manual` added as a CLI alias for the `default` permission mode.
- **v2.1.208+** — `rm -rf /` and `rm -rf ~`, including command- and process-substitution variants, prompt as a circuit breaker even under `bypassPermissions`.

> Source: https://code.claude.com/docs/en/plugins.md

- **v2.1.128+** — `--plugin-dir` accepts a `.zip` archive.

> Source: https://code.claude.com/docs/en/headless.md

- **v2.1.128** — stdin piping into `claude -p` capped at 10MB.
- **v2.1.163+** — a background Bash task started during `claude -p` is terminated ~5s after the final result plus stdin close (fix for never-exiting processes).
- **v2.1.219+** — `system/init` stream event includes `mcp_servers` / `mcp_server_errors`, letting CI fail when an `--mcp-config` entry is invalid.

> Source: https://code.claude.com/docs/en/skills.md

- **v2.1.129+** — `${CLAUDE_SKILL_DIR}` substitutes inside `allowed-tools` Bash rules.
- **v2.1.145+** — `/run-skill-generator` records a per-project run recipe at `.claude/skills/run-<name>/`.
- **v2.1.196+** — `${CLAUDE_PROJECT_DIR}` substitutes inside `allowed-tools`.
- **v2.1.199+** — up to 6 skills can be chained in one message.
- **v2.1.203+** — a nested skill that clashes with a root-level skill gets a directory-qualified name (`apps/web:deploy`), and typing the unqualified `/deploy` auto-includes an instruction to invoke matching directory-qualified variants.
- **v2.1.215+** — `/verify` and `/code-review` run only when explicitly invoked; Claude cannot auto-trigger them.
- **v2.1.218+** — boolean frontmatter fields accept `yes/no/on/off/1/0` in any case; `background: false` is available on `context: fork` skills.

> Source: https://code.claude.com/docs/en/settings.md

- **v2.1.181+** — `/config key=value` changes a single setting from the prompt.

> Source: https://code.claude.com/docs/en/mcp.md

- **v2.1.186+** — `claude mcp login <server>` runs the OAuth flow directly from the shell.
- **v2.1.212+** — a main-conversation MCP call still running after 2 minutes automatically moves to a background task (`CLAUDE_CODE_MCP_AUTO_BACKGROUND_MS`, `0` disables).

> Source: https://code.claude.com/docs/en/sandboxing.md

- **v2.1.191+** — approval of a new domain in a sandboxed session sticks for the rest of the session.
- **v2.1.199+** — `mode: "mask"` supported for sandbox credential **env vars**.
- **v2.1.216+** — `sandbox.filesystem.disabled` is honored only from user/managed/`--settings` sources, never from project `.claude/settings.json` or `.claude/settings.local.json`.
- **v2.1.221+** — `mode: "mask"` supported for sandbox credential **files**.

> Source: https://code.claude.com/docs/en/plugin-marketplaces.md

- **v2.1.193+** — `renames` in `marketplace.json` performs auto-migration; earlier versions show `plugin-not-found`.

> Source: https://code.claude.com/docs/en/sub-agents.md

- **v2.1.178+** — project subagents load by walking up from cwd, and the definition closest to cwd wins a name clash.
- **v2.1.196+** — `CLAUDE_CODE_SUBAGENT_MODEL=inherit` is treated the same as the variable being unset.
- **v2.1.198+** — `Explore` inherits the main conversation's model capped at Opus on the Claude API (previously always Haiku); `/agents` no longer opens an interactive wizard; subagents run in the background by default (which also applies the background tool filter); subagents inherit the main conversation's extended-thinking setting.
- **v2.1.203+** — the worktree-isolation cwd check covers the whole repository rather than only the launch directory.
- **v2.1.210+** — Claude Code scans each subagent's final report for instruction-shaped content and defuses imitation tags before Claude reads it.
- **v2.1.218+** — project-level subagent frontmatter hooks require workspace-trust acceptance.

> Source: https://code.claude.com/docs/en/server-managed-settings.md

- **v2.1.139** — `claude auth` subcommands are exempt from `forceRemoteSettingsRefresh` fail-closed startup.
- **v2.1.198** — three categories of cached `env` values (proxy/TLS, API routing/provider selection, auth credentials) are withheld until the server confirms the payload for the session.

> Source: https://code.claude.com/docs/en/authentication.md

- **v2.1.212+** — terminal, VS Code, and Agent SDK login paths enforce both `forceLoginMethod` and `forceLoginOrgUUID`. `claude setup-token` and `/install-github-app` enforce only `forceLoginMethod`.

> Source: https://code.claude.com/docs/en/commands.md

- **v2.1.199+** — up to 6 skills chained per message (matches the skills gate above).
- **v2.1.198+** — `/agents` is a reminder only, with no wizard.
- **v2.1.221+** — `/autocompact [auto|<tokens>]` available.

> Source: https://code.claude.com/docs/en/monitoring-usage.md

- **v2.1.212+** — the OTel HTTP exporter sends a `Content-Length` header instead of using chunked encoding.
