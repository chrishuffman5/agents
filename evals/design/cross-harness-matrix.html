01 · HYPOTHESIS

A good skill buys speed, not just accuracy

The current harness proves the skills layer improves accuracy and cost against a same-model baseline. This design extends it to prove a sharper claim about speed:

A model reading a well-curated skill can run at low/medium effort and still match — or beat — the accuracy of a bare model at high effort, because the skill has already done the thinking the model would otherwise re-derive. Less reasoning to re-derive means fewer thinking tokens, which means faster responses at equal accuracy.

Three measurable predictions fall out of that, and the matrix is shaped to test each:

  • P1 — Iso-accuracy speedup. For each harness × model: the fastest skill config that reaches the accuracy of the best no-skill config is materially faster (target: ≥30% wall-clock reduction).
  • P2 — Effort-collapse. With the skill installed, the accuracy gap between low and high effort shrinks toward zero; without it, the gap stays wide. Overthinking has nothing left to add when the skill already states the answer's shape.
  • P3 — Small-model uplift. Skill + small/cheap model (Haiku 4.5, Luna, local) approaches no-skill + flagship accuracy — the "skill as equalizer" effect, measured per domain.

03 · THE MATRIX

Cell math

One cell = harness × model × effort × skill-mode. One run = cell × prompt × attempt. Prompts come from the existing evals/suites/*.json (graded, one-shot, fresh session per attempt — unchanged). With the pinned roster and one 10-prompt pilot suite:

LaneCells× prompts× attemptsRunsExecution
Cloud (3 + 3 + 6) × 3 × 2 = 72 10 1 720 parallel, throttled per provider
Local (codex profiles + pi) 3 × 2 × 2 × 2 = 24 10 1 240 strictly serial; models grouped so each loads into VRAM once

Claude Code contributes 3 cloud models, Codex 3 (Sol/Terra/Luna), Pi bridges all 6; local models run E1/E2 only (local "high thinking" mostly measures the GPU). The local lane's two harnesses on identical models give the harness-tax readout for free: codex-vs-pi overhead on the same weights.

04 · RUNNER

Queue-fed PowerShell orchestrator

A SQLite database is the queue and the ledger: a seeding script expands suites × matrix into one row per planned run (the exact CLI command pre-rendered); a PowerShell 7 dispatcher drains the queue with a thread pool for cloud lanes and a single-threaded lane for local models. Crash-safe by construction — re-running the dispatcher picks up status = queued|error rows and never re-executes done ones.

⚠ ENV VARS ARE PROCESS-WIDE — THE ONE CORRECTNESS RULE
  • Three cell types are configured through environment variables: claude→Ollama (ANTHROPIC_BASE_URL), codex skill-arm (CODEX_HOME), and any provider key override. PS7 thread-parallelism (ForEach-Object -Parallel, Start-ThreadJob) shares one process environment — a thread flipping ANTHROPIC_BASE_URL would silently reroute every concurrent claude cloud run to localhost.
  • Rule: workers never mutate $env: in the pool. Every run executes in a child pwsh process (invoke-run.ps1) that sets its own env from queue columns. Threads only schedule; processes execute.

Strategy 0 — command templating (the codex -p special case lives here)

function New-CellCommand {
    param($Cell)   # harness, model, effortLiteral, skillMode, skillPath, prompt, workdir
    $q = '"' + ($Cell.prompt -replace '"', '\"') + '"'
    switch ($Cell.harness) {
        'claude' {
            $f = @('-p','--bare','--no-session-persistence','--output-format','json','--model',$Cell.model)
            $f += if ($Cell.skillMode -eq 'skill') { @('--plugin-dir','C:\evals\plugins') }
                  else                              { '--disable-slash-commands' }
            "claude $($f -join ' ') $q"
        }
        'codex' {   # NB: -p here means --profile, never --print; skill arm = CODEX_HOME in env_json
            $f = @('e','--ephemeral','--skip-git-repo-check','-C',$Cell.workdir,
                   '-s',$Cell.sandbox,'--json','-o','last_message.txt')
            $f += if ($Cell.lane -eq 'local') { @('--profile',$Cell.codexProfile) }
                  else                           { @('-m',$Cell.model) }
            $f += @('-c',"model_reasoning_effort=`"$($Cell.effortLiteral)`"")  # composes over profiles too
            "codex $($f -join ' ') $q"
        }
        'pi' {      # default provider is google — ALWAYS pass provider or provider/model
            $f = @('-p','--no-session','--no-context-files','--mode','json',
                   '--model',$Cell.model,'--thinking',$Cell.effortLiteral)
            $f += if ($Cell.skillMode -eq 'skill') { @('--skill',$Cell.skillPath) }
                  else                              { '--no-skills' }
            "pi $($f -join ' ') $q"
        }
    }
}

Strategy 1 — seeding the queue

# seed-queue.ps1 — expand matrix.config.json × suites into evalq.sqlite (PSSQLite module)
Import-Module PSSQLite
$cfg = Get-Content .\matrix.config.json | ConvertFrom-Json
$db  = '.\evalq.sqlite'
Invoke-SqliteQuery -DataSource $db -Query (Get-Content .\schema.sql -Raw)

$rows = foreach ($cell in $cfg.cells) {          # cells pre-expanded: harness×model×effort×mode
  foreach ($suiteName in $cfg.suites) {
    $suite = Get-Content "..\suites\$suiteName.json" | ConvertFrom-Json
    foreach ($t in $suite.tasks) {
      for ($a = 1; $a -le $cfg.attempts; $a++) {
        [pscustomobject]@{
          run_id     = '{0}.{1}.{2}.{3}.{4}.a{5}' -f $cell.harness,$cell.model,$cell.effort_norm,$cell.skill_mode,$t.id,$a
          harness    = $cell.harness;  provider = $cell.provider; model = $cell.model
          effort_norm = $cell.effort_norm; effort_literal = $cell.effort_literal
          skill_mode = $cell.skill_mode;   lane = $cell.lane
          suite = $suiteName; task_id = $t.id; attempt = $a
          command  = New-CellCommand ($cell + @{ prompt = $t.prompt })
          env_json = ($cell.env | ConvertTo-Json -Compress)   # CODEX_HOME / ANTHROPIC_BASE_URL / keys
          workspace = "C:\evals\work\$($cell.harness)"; status = 'queued'
        }
      }
    }
  }
}
$rows | ForEach-Object { Invoke-SqliteQuery -DataSource $db -Query $insertSql -SqlParameters $_ }
Write-Host "$($rows.Count) runs queued"

Strategy 2 — flat thread pool (simplest; single-provider sweeps)

# dispatch-flat.ps1 — ForEach-Object -Parallel; one global throttle. Right answer when the
# sweep is one provider (no per-provider fairness needed). Each run still executes in a CHILD pwsh.
$queued = Invoke-SqliteQuery -DataSource $db -Query "SELECT run_id FROM runs WHERE status='queued' AND lane='cloud'"
$queued | ForEach-Object -Parallel {
    $run = Claim-Run -Db $using:db -RunId $_.run_id      # atomic: UPDATE…WHERE status='queued' RETURNING
    if (-not $run) { return }                            # another worker got it — fine
    $sw  = [Diagnostics.Stopwatch]::StartNew()
    $raw = & pwsh -NoProfile -File .\invoke-run.ps1 -Db $using:db -RunId $run.run_id
    $sw.Stop()
    Complete-Run -Db $using:db -RunId $run.run_id -WallMs $sw.ElapsedMilliseconds -Raw ($raw -join "`n")
} -ThrottleLimit 6

Strategy 3 — per-provider slot pool (the full sweep)

# dispatch-pool.ps1 — Start-ThreadJob with per-provider caps + live progress + stall detection.
# Use for the mixed sweep: anthropic and openai fill independently; neither starves the other.
$caps = @{ anthropic = 4; openai = 4 }                   # per-provider concurrency
$jobs = @{}
while ($true) {
    foreach ($p in $caps.Keys) {                         # fill free slots per provider
        $running = @($jobs.Values | Where-Object { $_.Provider -eq $p -and $_.Job.State -eq 'Running' })
        for ($i = $running.Count; $i -lt $caps[$p]; $i++) {
            $run = Claim-NextRun -Db $db -Provider $p -Lane cloud
            if (-not $run) { break }
            $jobs[$run.run_id] = @{ Provider = $p; Started = Get-Date
                Job = Start-ThreadJob -ArgumentList $db, $run.run_id {
                    param($db, $id)
                    $sw  = [Diagnostics.Stopwatch]::StartNew()
                    $raw = & pwsh -NoProfile -File .\invoke-run.ps1 -Db $db -RunId $id   # child process
                    $sw.Stop()
                    @{ WallMs = $sw.ElapsedMilliseconds; Raw = ($raw -join "`n") }
                } }
        }
    }
    foreach ($id in @($jobs.Keys)) {                     # harvest + timeout enforcement
        $e = $jobs[$id]
        if ($e.Job.State -in 'Completed','Failed') {
            $res = Receive-Job $e.Job; Remove-Job $e.Job
            Complete-Run -Db $db -RunId $id -WallMs $res.WallMs -Raw $res.Raw
            $jobs.Remove($id)
        } elseif ((Get-Date) - $e.Started -gt [timespan]::FromMinutes(10)) {
            Stop-Job $e.Job; Remove-Job $e.Job -Force
            Fail-Run -Db $db -RunId $id -Reason 'timeout'; $jobs.Remove($id)
        }
    }
    $depth = Get-QueueDepth -Db $db -Lane cloud
    Write-Progress -Activity 'cloud sweep' -Status "$depth queued / $($jobs.Count) running"
    if (-not $jobs.Count -and $depth -eq 0) { break }
    Start-Sleep -Milliseconds 250
}

Strategy 4 — the per-run child process (where env vars are allowed)

# invoke-run.ps1 — one run, one clean process. The ONLY place $env: is ever set.
param($Db, $RunId)
$run = Get-Run -Db $Db -RunId $RunId
foreach ($kv in ($run.env_json | ConvertFrom-Json).PSObject.Properties) {
    Set-Item "env:$($kv.Name)" $kv.Value    # e.g. CODEX_HOME=C:\evals\codex-home-skills
}                                            #      ANTHROPIC_BASE_URL=http://localhost:11434
Set-Location $run.workspace
Invoke-Expression $run.command               # stdout (JSON / JSONL) returns to the pool worker
exit 0                                       # codex exit codes are undocumented — never grade on $LASTEXITCODE

Strategy 5 — local lane: serial with VRAM warm-up

# dispatch-local.ps1 — one run at a time, grouped by model so each loads into VRAM once.
$models = Invoke-SqliteQuery -DataSource $db -Query "
  SELECT DISTINCT model FROM runs WHERE status='queued' AND lane='local' ORDER BY model"
foreach ($m in $models.model) {
    & ollama run $m --keepalive 45m "ok" | Out-Null        # warm-up: load before the clock ever starts
    while ($run = Claim-NextRun -Db $db -Lane local -Model $m) {
        $sw  = [Diagnostics.Stopwatch]::StartNew()
        $raw = & pwsh -NoProfile -File .\invoke-run.ps1 -Db $db -RunId $run.run_id
        $sw.Stop()
        Complete-Run -Db $db -RunId $run.run_id -WallMs $sw.ElapsedMilliseconds -Raw ($raw -join "`n")
    }
    & ollama stop $m                                        # evict before the next model claims the GPU
}

Strategy 6 — serial timing confirmation (the P1 numbers)

# timing-pass.ps1 — headline cells re-run at concurrency 1, N repeats, median reported.
# The parallel sweep decides WHICH cells win; this pass decides what number gets quoted.
param([string[]]$CellIds, [int]$Repeats = 3)
foreach ($cellId in $CellIds) {
    foreach ($run in Get-CellRuns -Db $db -CellId $cellId) {
        $samples = 1..$Repeats | ForEach-Object {
            $sw = [Diagnostics.Stopwatch]::StartNew()
            & pwsh -NoProfile -File .\invoke-run.ps1 -Db $db -RunId $run.run_id | Out-Null
            $sw.Stop(); $sw.ElapsedMilliseconds
        }
        $median = ($samples | Sort-Object)[[math]::Floor($samples.Count / 2)]
        Add-TimingSample -Db $db -RunId $run.run_id -MedianMs $median -Samples ($samples -join ',')
    }
}

Per-harness result parsing — verified field maps

function Read-RunResult {
    param($Run, [string]$Raw)
    switch ($Run.harness) {
        'claude' {   # --output-format json → one object
            $j = $Raw | ConvertFrom-Json
            @{ answer = $j.result
               tokens_in = $j.usage.input_tokens;  tokens_out = $j.usage.output_tokens
               cache_read = $j.usage.cache_read_input_tokens
               cost_usd = $j.total_cost_usd;       api_ms = $j.duration_ms }
        }
        'codex' {    # --json → JSONL events; answer from the -o file; tokens from turn.completed
            $turn = $Raw -split "`n" | Where-Object { $_ } | ForEach-Object { $_ | ConvertFrom-Json } |
                    Where-Object type -eq 'turn.completed' | Select-Object -Last 1
            @{ answer = Get-Content (Join-Path $Run.workspace 'last_message.txt') -Raw
               tokens_in = $turn.usage.input_tokens; tokens_out = $turn.usage.output_tokens
               cache_read = $turn.usage.cached_input_tokens }
        }
        'pi' {       # --mode json → session header + typed events; message_update is DELTA-ONLY,
                     # so take message_end (complete message), never accumulate by hand unless streaming
            $end = $Raw -split "`n" | Where-Object { $_ } | ForEach-Object { $_ | ConvertFrom-Json } |
                   Where-Object type -eq 'message_end' | Select-Object -Last 1
            @{ answer = $end.message.content }
        }
    }
}

Raw stdout is archived per run alongside the parsed fields, so a mapping bug is recoverable without re-spending tokens. Codex exit codes are undocumented (per its own skill corpus) — outcomes are graded from the answer artifact, never from $LASTEXITCODE.

The readout that proves it

  • Headline: per harness × model, a two-column card — best no-skill config vs fastest skill config at ≥ that accuracy — with the wall-clock delta as the big number. That's P1 in one glance.
  • Effort-collapse chart: accuracy vs effort (E1→E3), two lines per model (skill / no-skill). P2 is the skill line running flat while the no-skill line climbs.
  • Equalizer table: small-model + skill rows (Haiku 4.5, Luna, locals) ranked against flagship no-skill rows (P3).
  • Harness tax: same local model on codex vs pi — overhead attributable to the harness itself, free from the local lane's design.
  • All of it lands in the existing docs/ dashboard as a new page fed by summary.csv.
